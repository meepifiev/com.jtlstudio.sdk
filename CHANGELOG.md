# Changelog

## [1.4.0] - 2026-09-29

### Changed

- Порядок строк в карточке Project settings повторяет блок WebGL Settings в Player Settings: Enable Exceptions, Compression Format, Name Files As Hashes, Data Caching, Debug Symbols, Decompression Fallback, дальше идут Managed Stripping Level, Run In Background и Memory Size.
- Debug Symbols стал выпадающим списком Off, External, Embedded вместо галки. Галка умела только Off и External, а Embedded выбрать было нельзя. `PlayerSettingsPreset.DebugSymbols` теперь `DebugSymbolMode`, а не `bool`; в конфигурациях старое значение переезжает само, потому что выключено это Off, а включено External.
- В разделе Build список Debug Symbols переехал в блок Runtime к Managed Stripping и Enable Exceptions.

### Added

- В пресет добавлена строка Name Files As Hashes. Раньше эта галка в разделе Build писала прямо в Player Settings мимо конфигурации, теперь она часть пресета, как соседние поля. Галка Apply у неё по умолчанию снята, поэтому обновление ничего не перезапишет.

## [1.3.0] - 2026-09-29

### Added

- В пресете конфигурации появилась строка Enable Exceptions: значения как в Unity (None, Explicitly Thrown Exceptions Only, Full Without Stacktrace, Full With Stacktrace). Стоит первой, над Compression Format, как в Publishing Settings. Тот же список продублирован в разделе Build, блок Runtime.
- Галка Apply у этой строки по умолчанию снята, как у Memory Size: SDK не трогает `PlayerSettings.WebGL.exceptionSupport`, пока вы её не поставите, поэтому обновление не перезапишет значение в существующих проектах. У новых конфигураций в пресет кладётся Explicitly Thrown Exceptions Only.

## [1.2.0] - 2026-09-25

### Added

- У конфигурации появилось поле Yandex Metrica counter: раздел Configurations, карточка Analytics. Счётчик читается модулем `com.jtlstudio.sdk.analytics`, который шлёт в него цели; пустое поле означает, что цели не отправляются.
- В каталоге модулей появился Analytics.

## [1.1.1] - 2026-09-24

### Fixed

- Список модулей отваливался с `403 Forbidden`: он и версии модулей читались через GitHub REST API, а тот даёт 60 анонимных запросов в час на адрес, и каждая перекомпиляция тратила несколько. Теперь `modules.json` берётся с `raw.githubusercontent.com`, а версии модулей из ленты тегов `github.com/<repo>/tags.atom` - у этих адресов такого лимита нет.
- Если список не скачался, тулкит показывает модули из `modules.json`, который лежит в самом пакете, а не пустую карточку с ошибкой.
- Проверка релизов SDK больше не ходит в сеть после каждой перекомпиляции: результат живёт час, как и было задумано. При исчерпанном лимите вместо `403 Forbidden` пишется, что GitHub разрешает 60 анонимных запросов в час.

## [1.1.0] - 2026-09-24

### Added

- В разделе Package Manager у модулей появились логотипы и кнопка обновления. Логотип берётся из самого модуля (`Editor/Logo.png`), пока его нет - показывается логотип шаблона. Новая версия ищется по тегам репозитория модуля, поэтому релизы для модулей заводить не обязательно; у встроенных и локальных модулей кнопки нет.

## [1.0.0] - 2026-09-23

Первый публичный выпуск.

- Один API для Яндекс Игр, YouTube Playables и редактора: реклама, покупки, облачные сохранения, языки, пауза, лидерборды, флаги, игрок, площадка, устройство, время, звук, отзыв, ярлык игры, ссылки.
- Окно `JTL SDK › Toolkit`: конфигурации площадок, сборка с проверками, симуляция в редакторе, шаблон загрузочного экрана, каталог модулей, анализатор кода.
- Симуляция в редакторе отвечает за площадку: реклама, покупки, сейвы, лидерборды, флаги, язык, устройство.
- Шаблон WebGL: логотип, фоны, прогресс-бар, текст загрузки, фиксация пропорций, pixel ratio.
- API работает только после `JTLSDK.Create()`; обращение до запуска и после остановки бросает исключение.
- Модули ставятся из раздела Package Manager по каталогу `modules.json`.

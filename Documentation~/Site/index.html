Для чего нужен JTL SDK

Пакет для Unity, который прячет различия между веб-площадками за одним набором вызовов.

У каждой площадки свой JS-SDK, свой формат сохранений, свои правила рекламы, паузы и сжатия сборки. JTL SDK описывает эти правила как конфигурации: вы делаете одну активной, окно SDK применяет к проекту нужные настройки WebGL и define-символ, а в сборку попадает только мост этой площадки. Код игры при этом не меняется.

Вызов проходит четыре слоя. Статический фасад JTLSDK отдаёт модуль, например JTLSDK.Ads. Модуль проверяет состояние и аргументы и держит общие правила: паузу на время рекламы и оплаты, сохранение перед списанием покупки, очередь GameReady. Провайдер из активной конфигурации переводит вызов в API площадки. Мост (.jspre площадки и общий jtlsdk.jslib) вызывает JS-SDK и возвращает ответ в колбэк на главном потоке Unity. В редакторе провайдеры заменяются симуляцией, её ответы задаются в разделе Simulation.

Установка и настройка

Через Unity Package Manager по git-ссылке. Unity 2021.3.18f1 или новее, платформа WebGL.

Перед установкой

  • В Console не должно быть ошибок компиляции. Пока проект не компилируется, Unity не выполняет editor-код пакета: окно SDK не откроется, а разделы и провайдеры покажут не то, что есть на самом деле. Сначала почините существующие ошибки, потом ставьте пакет.
  • Другой копии JTL SDK в проекте быть не должно. Пакет из Package Manager и его же копия, импортированная в Assets, дают дублирующиеся типы и ошибки компиляции. Держите одну версию.
  • Другие SDK площадок конфликтуют. Плагины со своим WebGL-кодом (.jslib и .jspre), которые сами обращаются к API Яндекса или YouTube, инициализируют тот же JS-SDK второй раз. В браузере это видно как ошибки про повторную инициализацию, двойные паузы и повторные запросы рекламы.
  • Переезд со старого плагина. Старый плагин можно временно оставить рядом и переносить код по частям, но WebGL-сборку с двумя SDK сразу выкладывать не стоит: пока в проекте два платформенных слоя, поведение непредсказуемо.

Инициализация

Четыре шага до первой сборки.

1

Создайте конфигурацию

Configurations, New configuration, выберите площадку. На площадку создаётся одна конфигурация, первая созданная становится активной сама. Конфигурация хранится в Assets/Settings/JTLSDK/Configurations и содержит провайдеры модулей, языки площадки и пресет Player Settings.

Активация ставит для WebGL define-символ JTLSDK_YANDEX_GAMES или JTLSDK_YOUTUBE_PLAYABLES и применяет пресет. Яндекс: Compression Format Brotli, Managed Stripping Level Medium. YouTube: Compression Format Disabled, Managed Stripping Level High. Для обеих площадок WebGL Template JTLSDK, Data Caching и Run In Background включены, Decompression Fallback выключен, Debug Symbols Off.

2

Установите шаблон

Template, Install копирует шаблон загрузки в Assets/WebGLTemplates/JTLSDK. Логотип, фоны, прогресс-бар, пропорции холста и pixel ratio задаются в том же разделе и подставляются в index.html готовой сборки, файлы в Assets во время сборки не меняются. Если после обновления пакета шаблон устарел, он обновляется сам при загрузке редактора и перед сборкой из окна SDK.

3

Запустите SDK

JTLSDK.Create() вызывается один раз в первой сцене. Он загружает Assets/Resources/JTLSDK/JTLSDKSettings.asset, создаёт провайдеры активной конфигурации, подключает мост площадки и запускает все модули одновременно. Повторный Create() бросает InvalidOperationException, поэтому проверяйте JTLSDK.IsCreated.

JTLSDK.WhenReady вызывает колбэк, когда ни один модуль не остался в Pending. Модуль, который не ответил за Initialization timeout (15 с по умолчанию), помечается Failed, так что колбэк приходит всегда. GameReady() вызывается один раз, когда игрок уже может играть.

Bootstrap.csSamples~/Examples
using UnityEngine;

namespace JTLStudio.SDK.Samples.Examples
{
    public class Bootstrap : MonoBehaviour
    {
        private void Awake()
        {
            if (JTLSDK.IsCreated == false)
            {
                JTLSDK.Create();
            }

            JTLSDK.WhenReady(OnReady);
        }

        private void OnReady()
        {
            Debug.Log("Platform: " + JTLSDK.Platform.Current + ", language: " + JTLSDK.Language.Current);
            JTLSDK.GameEvents.GameReady();
        }
    }
}
4

Соберите

Раздел Build, кнопка Build Project.

Модули SDK

Каждый модуль доступен как статическое свойство JTLSDK и реализует IModule. До Create() и после остановки игры модули отвечают как неподдерживаемые и пишут предупреждение в консоль, поэтому отписки в OnDisable безопасны. Исключение бросает только WhenReady без Create().

StateIsSupportedIsReadyКогда
PendingtruefalseПровайдер ещё запускается.
ReadytruetrueПровайдер ответил, модуль работает.
FailedtruetrueПровайдер вернул ошибку или не ответил за Initialization timeout. Вызовы не бросают исключений и возвращают безопасный результат.
UnsupportedfalsetrueПлощадка этого не умеет, или в конфигурации выбран провайдер Unsupported.

WhenReady(callback) модуля вызывает колбэк сразу, если модуль уже вышел из Pending, иначе при первом переходе в Ready, Failed или Unsupported. Колбэк приходит и при ошибке, поэтому что произошло, смотрите в State. Модули Pause, Device и Audio готовы сразу после Create(), Data становится Ready только после первой загрузки сейва.

Настраиваемые и готовые к работе

Purchases, Saves, Languages, Leaderboards и Flags требуют данных из окна SDK: каталога товаров, досок, флагов, языков, лимитов сейва. Ads, Game events, Pause, Time, Audio, Player, Platform, Review и Game label работают без настройки: в конфигурации для них выбирается провайдер, а у рекламы Яндекса ещё интервалы и sticky banner.

Константы

Generate constants в разделах Purchases, Leaderboards и Flags пишет Assets/Scripts/Generated/JTLSDKIds.cs с классами ProductIds, LeaderboardIds и FlagKeys в корневом namespace проекта (если он не задан, в Game). Имена строятся в PascalCase из букв и цифр id. Файл не обновляется сам: после правки каталога нажмите кнопку снова.

Порядок показа

Сначала проверки, без показа и без событий: модуль Pending даёт NotReady, формат не поддерживается даёт NotSupported, уже идёт показ даёт NotShown. Затем IsShowing становится true, ставится пауза Advertisement, геймплей останавливается, приходит Opened. После закрытия в обратном порядке: IsShowing false, геймплей возобновляется, пауза снимается, Closed, затем onResult. Колбэк приходит ровно один раз.

Интервалы на Яндексе

В настройках провайдера рекламы Яндекса в конфигурации: минимальный интервал между interstitial (60 с после последнего показанного) и пропуск interstitial после rewarded (60 с после досмотренного). Внутри интервала interstitial возвращает NotShown, Яндекс не вызывается. Sticky banner показывает баннер сразу при старте. На YouTube интервалы ведёт сама площадка, баннера нет.

RewardedDoubleCoins.csSamples~/Examples
using UnityEngine;

namespace JTLStudio.SDK.Samples.Examples
{
    public class RewardedDoubleCoins : MonoBehaviour
    {
        private const string CoinsKey = "Coins";
        private const string RewardId = "double_coins";

        public void OnDoubleCoinsClicked()
        {
            if (JTLSDK.Ads.IsRewardedSupported == false || JTLSDK.Ads.IsShowing)
            {
                return;
            }

            JTLSDK.Ads.ShowRewarded(RewardId, OnRewardedFinished);
        }

        private void OnRewardedFinished(AdResult result)
        {
            if (result != AdResult.Rewarded)
            {
                Debug.Log("No reward: " + result);
                return;
            }

            int coins = JTLSDK.Data.GetInt(CoinsKey);
            JTLSDK.Data.SetInt(CoinsKey, coins * 2);
            JTLSDK.Data.Save();
        }
    }
}

Внутриигровые покупки

Покупки за валюту площадки. Работают на Яндексе через ysdk.getPayments(), на YouTube модуль Unsupported.

Товар объявляется в разделе Purchases окна SDK: Product id (им пользуется код), Type (Non-consumable или Consumable), Yandex Games id (пустое поле значит тот же id) и Test price с валютой для редактора. При старте SDK запрашивает getCatalog() и getPurchases().

APIЧто делает
Purchase(productId, onSuccess, onError)Открывает оплату: purchase({ id }). До ответа игра на паузе с источником Purchase. Товар выдаётся в onSuccess. onError вызывается, если модуль ещё не готов, покупки не поддерживаются, id нет в каталоге, уже идёт другая покупка или игрок закрыл окно оплаты. Причина пишется в консоль.
GetProductData(productId)ProductData из каталога площадки: Id, Price (decimal), Currency и Formatted, готовая строка для кнопки. У неизвестного товара и до готовности модуля IsValid равен false.
IsAlreadyPurchased(productId)Есть ли товар в списке покупок площадки. Для Non-consumable это покупка навсегда. Consumable в списке только до списания.
RestorePurchases(onRestoreData)Перечитывает покупки площадки и отдаёт IRestoreData. Если покупок нет на площадке, приходит null.

Что происходит после оплаты

  1. Площадка подтверждает оплату, пауза снимается.
  2. SDK вызывает onSuccess, игра начисляет товар через JTLSDK.Data.
  3. SDK помечает покупку выданной и сохраняет сейв.
  4. Если товар Consumable и сохранение прошло, SDK списывает покупку: consumePurchase(token). Non-consumable не списывается никогда.

Восстановление покупок

Оплата могла пройти, а товар не дойти до игрока: оборвалась связь, игрок закрыл вкладку или игра упала. Такая покупка остаётся у площадки, и вернуть её нужно вручную:

Shop.csSamples~/Examples
using UnityEngine;

namespace JTLStudio.SDK.Samples.Examples
{
    public class Shop : MonoBehaviour
    {
        private const string CoinsProduct = "coins_1000";
        private const string RemoveAdsProduct = "remove_ads";
        private const string CoinsKey = "Coins";

        private void Start()
        {
            JTLSDK.WhenReady(OnReady);
        }

        public void OnBuyCoinsClicked()
        {
            JTLSDK.Payments.Purchase(
                productId: CoinsProduct,
                onSuccess: () => GiveProduct(CoinsProduct),
                onError: () => Debug.Log("Coins were not bought"));
        }

        public void OnRemoveAdsClicked()
        {
            JTLSDK.Payments.Purchase(
                productId: RemoveAdsProduct,
                onSuccess: () => GiveProduct(RemoveAdsProduct),
                onError: () => Debug.Log("Remove ads was not bought"));
        }

        public bool AreAdsRemoved()
        {
            return JTLSDK.Payments.IsAlreadyPurchased(RemoveAdsProduct);
        }

        public string CoinsPriceText()
        {
            ProductData product = JTLSDK.Payments.GetProductData(CoinsProduct);
            return product.IsValid ? product.Formatted : "";
        }

        private void OnReady()
        {
            if (JTLSDK.Payments.IsSupported == false)
            {
                gameObject.SetActive(false);
                return;
            }

            JTLSDK.Payments.RestorePurchases(OnRestoreData);
        }

        private void OnRestoreData(IRestoreData restoreData)
        {
            if (restoreData == null)
            {
                return;
            }

            foreach (string productId in restoreData.PendingProducts)
            {
                restoreData.RestoreProduct(productId, () => GiveProduct(productId));
            }
        }

        private void GiveProduct(string productId)
        {
            if (productId == CoinsProduct)
            {
                JTLSDK.Data.SetInt(CoinsKey, JTLSDK.Data.GetInt(CoinsKey) + 1000);
            }
        }
    }
}

IRestoreData.AllPurchases это все покупки игрока на площадке, PendingProducts только те товары, которые ещё не выданы. RestoreProduct(productId, onProductRestore) вызывает колбэк столько раз, сколько оплат этого товара не выдано, отмечает их выданными и списывает расходуемые. Повторный вызов ничего не выдаёт.

Выданные покупки SDK помечает в сейве игрока (ключ jtlsdk.granted), поэтому товар не выдаётся дважды, даже если списать покупку на площадке не удалось. Начисляйте товар только через JTLSDK.Data: тогда начисление и отметка о выдаче уходят на площадку одним документом.

Вызывайте RestorePurchases один раз после JTLSDK.WhenReady. Если этого не сделать, SDK через несколько секунд напишет в консоль предупреждение о невыданных покупках.

В редакторе

Покупки симулируются и хранятся в PlayerPrefs (JTLSDK.Prototype.Purchases). В разделе Simulation, Purchases выбирается Ask every time (окно с вариантами ответа во вкладке Game) или Use selected result. Вариант paid, restored on next launch проверяет восстановление: покупка записывается как оплаченная, onError срабатывает, а товар приходит в RestorePurchases при следующем запуске Play Mode.

Сохранение прогресса

Ключ-значение в облаке игрока. Все ключи хранятся одним JSON-документом, ключ появляется при первом Set.

ПлощадкаЧтение и записьЛимит
Yandex Gamesplayer.getData(["jtlsdk"]), player.setData({ jtlsdk }, true)200 KiB, предупреждение после 100 KiB
YouTube Playablesytgame.game.loadData(), ytgame.game.saveData()3 MiB, предупреждение после 500 KiB
РедакторPlayerPrefs, ключ JTLSDK.Dataкак у площадки активной конфигурации

Размер считается в байтах UTF-8 всего документа. Документ больше лимита не отправляется, в консоли ошибка.

Загрузка

SDK загружает сейв при старте, модуль становится Ready после первой загрузки. LoadState: Loaded (данные есть), Empty (первый запуск), Failed (ошибка площадки или повреждённый документ). При Failed запись блокируется, чтобы не затереть прогресс в облаке, а загрузка повторяется каждые 30 с. Удачный повтор заменяет значения в памяти и вызывает Loaded.

До готовности модуля чтение возвращает значение по умолчанию с предупреждением, а запись не выполняется, в консоли ошибка. Читайте сейв в WhenReady.

Типы

SetInt хранит число как long, SetFloat как double, есть SetBool и SetString. SetObject пишет объект вложенным JSON через JsonUtility, поэтому сохраняются только поля, которые сериализует JsonUtility. GetObject<T> создаёт экземпляр конструктором без параметров и заполняет его. Если ключ хранит другой тип, Get* возвращает значение по умолчанию. Для удаления есть DeleteKey и DeleteAll, для проверки HasKey.

Запись

Set* меняет значение в памяти и ставит IsDirty. Через Autosave delay после последнего важного изменения (2 с по умолчанию, по реальному времени, Time.timeScale не влияет) документ уходит на площадку целиком.

У всех Set* есть необязательный параметр important, по умолчанию true:

ВызовЧто происходит
SetInt(key, value)Значение меняется в памяти и запускает автосохранение. Так пишутся монеты, открытые уровни, покупки.
SetInt(key, value, important: false)Значение меняется только в памяти, автосохранение не запускается. Уйдёт на площадку вместе со следующим важным изменением, при Save() или когда игрок скрыл вкладку. Так пишется то, что меняется часто: прогресс внутри уровня, позиция игрока, счётчик секунд.

Смысл флага в том, чтобы не гонять сеть на каждое мелкое изменение: у площадок есть свои ограничения на частоту записи, а документ отправляется целиком.

Save(onSaved) отправляет немедленно, например после уровня, и пишет всё, включая неважные изменения. Колбэк получает false, если сейв ещё не загружен, загрузился с ошибкой или уже идёт другая запись: в последнем случае запись встанет в очередь и колбэк придёт после неё. Событие Saved(bool) сообщает результат каждой записи, которую SDK начал.

Закрытие вкладки

В WebGL браузер не даёт игре времени на сеть: Unity вызывает только OnApplicationFocus, а OnApplicationQuit при закрытии вкладки не срабатывает вообще. Поэтому мост SDK слушает visibilitychange и pagehide: как только страница скрывается, изменённый сейв уходит на площадку и одновременно пишется в localStorage браузера.

При следующем запуске SDK сравнивает сейв площадки с этой резервной копией по номеру ревизии. Если площадка не успела записать последнюю версию, SDK берёт копию, отправляет её на площадку и удаляет. Копия хранится только в браузере игрока и нужна на случай обрыва.

Вход игрока

После Player.Authorize на Яндексе сейв перечитывается уже с аккаунта. Если на аккаунте есть сейв, он заменяет значения в памяти. Если нет, текущий прогресс сохраняется в аккаунт.

Раздел Saves в окне SDK показывает сейв редактора: значения можно поправить руками, очистить, выгрузить и загрузить JSON. В Simulation есть Simulate load failure и Empty save on start.

Локализация

Язык игрока от площадки. Language содержит 26 языков.

В разделе Languages задаются языки проекта, Default language и Replacements (замены для языков, которых нет в проекте), а в конфигурации те из них, что включены на площадке. Supported это языки проекта, включённые в активной конфигурации; если таких нет, только Default language.

Какой язык выбирается при старте

В редакторе язык старта задаётся полем Start language в разделе Languages и меняется в оверлее вкладки Game.

Настройки звука

Громкость игры, тишина в меню и звук, выключенный самим игроком на площадке.

Как это работает

Как и со временем, AudioListener принадлежит SDK: игра задаёт свои значения, а два свойства Unity пересчитываются из них при каждом изменении громкости, паузы игры, системной паузы и звука площадки:

AudioListener.pause  = системная пауза со звуком || JTLSDK.Audio.Paused;
AudioListener.volume = (системная пауза со звуком || звук выключен площадкой)
    ? 0f
    : JTLSDK.Audio.Volume;

«Системная пауза со звуком» это пауза площадки при включённом пункте «Ставить на паузу AudioListener» в разделе Pause. Ползунок громкости игрока хранится в Audio.Volume и возвращается сам, когда реклама закончилась или игрок вернулся во вкладку.

APIЧто делает
Audio.VolumeГромкость игры от 0 до 1, иначе исключение. Это значение для ползунка в настройках, его же сохраняйте в JTLSDK.Data.
Audio.PausedТишина по решению игры, например в своём меню паузы. На IsPaused и на площадку не влияет.
Audio.IsPlatformMuted, PlatformMuteChangedЗвук выключил игрок на самой площадке. YouTube: ytgame.system.isAudioEnabled() и onAudioEnabledChange. На Яндексе всегда false. Пока звук выключен площадкой, игра молчит при любой громкости.
Прямая запись в AudioListener.volume или AudioListener.pause перезапишется при следующем пересчёте. Code Analyzer заменяет такие места на JTLSDK.Audio.Volume и JTLSDK.Audio.Paused.

Время

Масштаб времени игры и время площадки.

Как это работает

Time.timeScale и AudioListener принадлежат SDK. Игра не пишет в них напрямую, потому что у площадки есть своя пауза: реклама, оплата, потеря фокуса, сигнал площадки. Если бы игра и SDK писали в одно и то же свойство, побеждал бы тот, кто записал последним, и после рекламы игра могла остаться замороженной или, наоборот, продолжить идти во время паузы.

Поэтому SDK хранит значение игры у себя, а Time.timeScale считает из двух величин каждый раз, когда любая из них меняется:

Time.timeScale = (системная пауза и включен пункт Time.timeScale в разделе Pause)
    ? 0f
    : JTLSDK.Time.Scale;

Пересчёт происходит в двух случаях: игра присвоила JTLSDK.Time.Scale или изменилось состояние паузы. Значение игры при этом никуда не девается: оно лежит в Time.Scale и возвращается в Unity, как только пауза снялась.

Что произошлоJTLSDK.Time.ScaleTime.timeScale
Игра идёт11
Игра открыла своё меню: Time.Scale = 000
Замедление боя: Time.Scale = 0.50.50.5
Во время замедления началась реклама0.50
Реклама закончилась0.50.5
Игрок свернул вкладку и вернулся0.50.5
Прямая запись в Time.timeScale живёт до следующего пересчёта: первая же пауза или первое присвоение Time.Scale её перезапишут. Раздел Code Analyzer в окне SDK находит такие места и заменяет их на JTLSDK.Time.Scale.

API

APIЧто делает
Time.ScaleМасштаб времени игры, не меньше 0 (отрицательный бросает исключение). По умолчанию 1. Пункт «Останавливать Time.timeScale» в разделе Pause включён по умолчанию; если его снять, во время системной паузы Unity получает Scale без изменений.
Time.Now, IsServerTimeDateTimeOffset. Яндекс: ysdk.serverTime() один раз при старте, дальше время идёт по часам устройства от этой точки, IsServerTime true. YouTube и редактор: время устройства, IsServerTime false.

Серверное время нужно для ежедневных наград и таймеров: часы устройства игрок может перевести.

Пауза

Системная пауза только автоматическая: игра не ставит её сама, а реагирует на неё.

ИсточникКогда ставится
AdvertisementРеклама на экране.
PurchaseОткрыто окно оплаты.
PlatformЯндекс: game_api_pause и game_api_resume. YouTube: ytgame.system.onPause и onResume.

IsPaused true, пока есть хотя бы один источник, Sources перечисляет активные. Changed(bool) вызывается только при смене общего состояния, а не каждого источника.

Что делает пауза

Настраивается в разделе Pause, по умолчанию всё включено: Time.timeScale становится 0; AudioListener.pause true и AudioListener.volume 0; все включённые EventSystem выключаются, а после паузы включаются ровно они же; курсор становится видимым и свободным.

После паузы SDK заново применяет свои значения: JTLSDK.Time.Scale, Audio.Volume и Audio.Paused, Device.CursorVisible и Device.CursorLock. Прямые записи в Time.timeScale, AudioListener и Cursor перезапишутся при следующей смене паузы, поэтому меняйте их только через SDK.

Своё меню паузы

Меню игры ставит паузу через JTLSDK.Time.Scale = 0 и JTLSDK.Audio.Paused = true. На IsPaused это не влияет, а после системной паузы значения игры вернутся.
